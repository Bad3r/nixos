# Editing documentation

## Editing passes

- Edit in separate passes, in this order: technical accuracy, completeness, structure, clarity, brevity.
- Keep each pass to one aspect.
  Combine passes and every aspect suffers.
- Run every sample and every non-destructive procedure before publishing the page.
  Check a destructive procedure against the code and options it names instead.
- Read only the headings to check the outline.
  An outline that reads like a maze means the page has more than one goal.
- Define each term once and use the same form everywhere.
  Do not alias it.
